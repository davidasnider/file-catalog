## 2024-05-15 - Streamlit Accessibility and Empty States
**Learning:** Adding `help` parameters to Streamlit UI components (like multiselects and columns) acts as accessible tooltips, significantly improving the experience for users unsure about filter functionality. Additionally, replacing generic "No documents found" messages with actionable empty states (e.g., "Try adjusting your criteria in the sidebar") reduces user frustration when filtering yields no results.
**Action:** Always provide `help` tooltips on interactive filters and ensure empty states guide the user on how to resolve the empty condition.
## 2024-05-16 - Semantic Meaning of UI Components
**Learning:** Using warning or error components (like `st.warning`) for normal empty states (e.g., when a search filter yields zero results) degrades the user experience by falsely implying a problem or error. Empty states should remain neutral (e.g., `st.info` or plain text) unless user action is critically required to resolve an actual issue. Furthermore, long strings passed to these components must be split across multiple lines to adhere to standard Python line length limits (e.g., <88 characters) to avoid CI linting failures.
**Action:** Retain `st.info` for filter-driven empty states. Improve these states by providing helpful context explaining *why* the state might be empty (e.g., "It may still be processing") rather than changing the component's semantic severity. Always use multi-line strings when adding contextual text to ensure linting compliance.
